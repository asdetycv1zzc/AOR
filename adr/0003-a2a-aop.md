# ADR-0003: A2A 1.0 With AOP v1

## Context
AOR requires standard Agent interoperability plus project, budget, lease, repository, and audit semantics.

## Decision
Use A2A 1.0 unchanged for cards, tasks, messages, artifacts, negotiation, and authentication. Carry AOR fields only in required extension `urn:aor:aop:v1`, validated by Draft 2020-12 Schema.

## Alternatives
A private Agent protocol duplicates A2A and reduces interoperability. Embedding control fields in free text is unverifiable.

## Security Consequences
Signed Agent Cards, expiry, nonces, stable message IDs, and lease-bound senders are mandatory. Unknown required capabilities fail closed.

## Operational Consequences
Conformance tests and a compatibility window are required for every AOP major version.

## Migration
Support the previous major during a declared migration window; conversions are pure, tested functions.

## Status
Accepted
