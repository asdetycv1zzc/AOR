# WP-06 Design

`Provider` validates immutable `SandboxSpec` values and delegates mechanics to a narrow backend. A Linux backend returns observed attestation; creation fails closed unless image, runtime, identity, filesystem, cgroup, syscall, mandatory-policy, device, namespace and socket controls all match. `DockerBackend` uses argument-vector process execution, a local digest-pinned image, rootless Docker with cgroups v2, an explicit seccomp profile and an AppArmor/SELinux option. It creates an ephemeral writable workspace and `/tmp`, starts the container, and then verifies `docker inspect` before attesting. Direct `ALLOWLIST` networking is unsupported by this backend and fails closed; broker-mediated access remains available outside the sandbox.

`WindowsNativeBackend` can be constructed only on Windows. It inherits only named environment variables, tracks child processes started through the provider, and stores work under one configured root. These are lifecycle controls, not isolation. The provider discards backend hardening claims and always emits `NONE` with the normative risk disclosure. Provider state prevents new operations once termination or destruction starts while allowing termination to interrupt an in-flight execution.
